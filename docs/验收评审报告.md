## 二、红线问题（合入前必须处理）

### R1 ★ 测试由绿转红：`52 passed` → `1 failed`

```
基线   aegis@4f004cd : 52 passed, 7 skipped, 1 warning in 100.99s
交付物 同机同环境   : 1 failed, 51 passed, 7 skipped, 1 warning in 101.17s
FAILED tests/test_panel.py::test_write_mtime_conflict_guard - OSError: [Errno 22] Invalid argument
        app/routes/file_routes.py:232:  when = time.strftime("%H:%M:%S", time.localtime(current / 1e9))
```

根因：把乐观锁从**秒**改成**纳秒**时，只改了生产代码与 `/api/files/read` 的返回，**没改既有测试的语义**：

- `tests/test_panel.py:1149` 取到的 `mtime` 现在是纳秒（≈1.79e18）
- `:1153` 仍按秒用：`os.utime(target, (mtime + 10, mtime + 10))` → 把文件 mtime 设到"公元 55 亿年"
- Windows：`utime` 被接受，随后 `time.localtime(1.7e18)` 抛 `OSError` → 接口 500 → 断言失败
- Linux：`utimensat` 对 `tv_sec > KTIME_SEC_MAX(≈9.2e9)` 返回 `EINVAL`，`:1153` 这一行就会抛错（此条为推理，建议在服务器上复跑确认）

结论：报告里"pytest 59 用例全绿"**不成立于本仓库/本平台**（59 = 51+7+1 的收集数是对的，但全绿是错的）。

顺带暴露一个**生产健壮性小洞**（同一行）：409 分支直接用 `time.localtime()` 格式化磁盘 mtime，文件时间戳只要越界（异常文件系统、被 `utime` 写坏、未来时间），**409 会变成 500**。基线用 `{current}` 直接插值，没有这个问题 —— 属于本次改动引入。

**修法**（2 行）：
```python
# tests/test_panel.py:1153
os.utime(target, ns=(mtime + 10_000_000_000, mtime + 10_000_000_000))
# app/routes/file_routes.py:232
try:
    when = time.strftime("%H:%M:%S", time.localtime(current / 1e9))
except (OSError, OverflowError, ValueError):
    when = "未知时间"
```

### R2 ★ 日志白名单的"敏感目录/隐藏目录"校验**没有覆盖配置导入路径**

报告 P1 第 6 条自称已修："改为「与敏感目录存在包含关系即拒」+ 隐藏目录全拒"，目的是堵住"公网只读用户读私钥/面板密码哈希"。**该修复只作用于 `PUT /api/panel/prefs` 一条路径。**

代码事实：
- `boot.py:636 set_pref_with_check()` 全仓库只有**一个**调用点：`panel_routes.py:188`（PUT /prefs）
- `panel_routes.py:434 config.data = merged; config.save()` 直接整体替换配置，`log_dirs` 从上传的 `config.json` 原样落地 —— **绕过了该校验器**
- `log_routes.py:20 _allowed_log_path()` 只判断"是否在白名单目录内"，**读取时不再校验白名单本身是否敏感**

我实测（`D:\sp-audit\import_bypass2.py`，真服务 + 真 HTTP）：

```
A0) PUT security.log_dirs=[<普通目录>]            -> HTTP 200   （对照组，字段名/流程正确）
A)  PUT security.log_dirs=[...\logs\.ssh]         -> HTTP 400   「不能把隐藏目录加入日志白名单」
A2) PUT security.log_dirs=['/etc/ssh']            -> HTTP 400   「与敏感目录 /etc 存在包含关系」
B)  POST /api/panel/config/import 顶层 log_dirs=[...\logs\.ssh] -> HTTP 200  ← 同一个值，导入路径放行
C)  GET /api/logs/file?path=...\.ssh\id_rsa       -> HTTP 200   content: "-----BEGIN OPENSSH PRIVATE KEY-----\nFAKE-SECRET"
D)  切成 public 模式后：panel/prefs -> 403，但 logs/file -> HTTP 200（内容照旧返回）
```

即：**公网只读模式下，登录用户仍可经日志接口读取被导入放行的任意目录**（例如 `/etc/serverpanel` 里的 `password_hash`、`agent_token`；`/etc/ssh` 里的私钥）。

定级与还原：
- 触发前提是"有人导入了一份带敌意 `log_dirs` 的配置"，导入接口本身要求内网模式管理员 → **不是提权链，是持久化的纵深防御缺口**；
- 基线同样只在 PUT 路径校验，**不是本次引入的回归**；
- 但报告把它写成"已修"，实际未闭环 —— 这条恰好是它自己 `bf082ae` 想修的那类问题。

**修法**（任一即可，建议两个都做）：
1. `import_config` 里对 `merged.get("log_dirs")` 与 `merged["prefs"]["security.log_dirs"]` 复用 `boot.set_pref_with_check` 的同一段判定（把判定抽成 `_assert_log_dirs_ok(dirs)`）；
2. `_allowed_log_path()` 里加一行读取时兜底：解析出的 `real` 落进敏感目录/隐藏目录即拒（whitelist 自证）。
